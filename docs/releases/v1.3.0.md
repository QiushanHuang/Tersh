# Tersh v1.3.0

Release date: 2026-10-28

Tersh v1.3.0 adds a hardware manager to the host dashboard and brings the
post-v1.2.0 file, log, navigation and SSH workflow improvements into a stable
release.

## Hardware manager

Run `tersh --c` and press **H**. Inspect each configured device's CPU model,
physical/logical core counts, sampled CPU usage, RAM capacity and occupancy,
and individual GPUs with available utilization, VRAM and temperature readings.
Wide terminals show a device summary; narrow terminals support wrapped,
scrollable hardware details.

- `j` / `k` or arrow keys select a device; PageUp / PageDown scroll details.
- Enter refreshes the selected device, `r` refreshes all, `P` pauses automatic
  refresh, and `q` returns to the device list.
- Missing commands and unsupported counters remain `unknown`. Failed refreshes
  retain and label the last successful reading and its age.
- CPU percentages come from an interval sample, independently of load average.
  Linux RAM excludes reclaimable cache; macOS physical occupancy includes cache
  and is labeled separately from memory pressure.
- NVIDIA, Apple and supported Linux DRM driver counters are collected without
  root or a resident agent. Apple GPU memory is shared RAM, never invented
  dedicated VRAM. WSL exposes only the hardware visible to its environment.
- Hardware collection uses the existing SSH inventory and bounded probe
  lifecycle. The remote host does not need Tersh installed for these readings.

See the [hardware guide](../hardware-manager.md) for platform-specific limits.

## Validation

The release candidate passed 409 Rust tests, 119 Python tests, formatting,
strict Clippy and an optimized build on macOS. Installed-binary terminal checks
covered hardware readings, pause/manual refresh, 40-column scrolling, returning
to the host list and terminal restoration.

Read-only live collection succeeded on a nine-device inventory spanning macOS,
Linux servers/NAS and WSL. CPU and RAM readings were available on all nine;
Apple and NVIDIA GPU counters were checked where supported. This also exposed
WSL's unidentified virtual DRM display node, now excluded from physical GPU
inventory and covered by a regression test. Unknown Intel/ASPEED driver counters
remain unknown.

GitHub CI checks Rust 1.88 on macOS and Linux, builds all three download targets
and runs the produced binary's version/help/hardware-keymap smoke check when
the runner architecture matches. Linux ARM64 is cross-compiled; these checks do
not claim a native Linux ARM64 hardware test.

## Other changes since v1.2.0

- Keep directory/preview verification and log reads off the interactive thread;
  reject stale results and preserve navigation focus and failed path input.
- Add recent/pinned places (`b` / `B`), session task history (`J`), validated
  retries and no-overwrite result exports.
- Add paused/searchable log following (`L`) and structured JSON/CSV/diff
  previews (`f`) with bounded buffers and raw fallback.
- Improve searchable actions, effective shortcut hints, narrow layouts and the
  collapsible inspector (`I`).
- Retain host metrics during checking; add attention (`a`), events (`E`), pause
  (`P`), fair refresh/backoff and cleanup of owned probe processes on exit.
- Allow slow jump connections 15 seconds to connect and 30 seconds per probe.
- Apply recognized WSL SSH lifecycle patches during installation, with backups
  and `--check-install-patches` for inspection. The installer does not connect
  to or update other devices automatically.

## Download and install

| Platform | Archive |
| --- | --- |
| macOS Apple Silicon | `tersh-v1.3.0-macos-arm64.tar.gz` |
| Linux x86_64, static musl | `tersh-v1.3.0-linux-x86_64.tar.gz` |
| Linux ARM64, static musl | `tersh-v1.3.0-linux-arm64.tar.gz` |

Each archive includes `tersh`, `install.sh`, `LICENSE` and `INSTALL.txt` and has
a companion SHA-256 file. Verify the checksum, extract, then run `./install.sh`.
The installer reuses the existing writable Tersh directory; set
`TERSH_INSTALL_DIR` to choose one explicitly. macOS downloads are not Developer
ID signed or notarized. Native Windows binaries are not included; use the Linux
x86_64 package inside WSL.

```sh
./install.sh
tersh --version
tersh --c
```

Source installation (Rust 1.88 or newer):

```sh
cargo install --locked --git https://github.com/QiushanHuang/Tersh.git --tag v1.3.0 --bin tersh --force
tersh --install-patches
```

Manual copies and Cargo installs require the explicit patch command above.
Unsupported driver data, virtualized topology and host reachability remain
visible limitations rather than fabricated measurements. See
[configuration](../configuration.md) and [WSL SSH](../wsl-ssh.md).

## 中文摘要

本版在 `tersh --c` 中新增 **H 硬件管理器**：查看每台设备的 CPU 型号、核心数和
使用率、内存容量与占用，以及每块 GPU 的利用率、显存和可用温度。支持设备切换、
手动/自动刷新、暂停、窄屏滚动和旧数据标识。Apple GPU 共享内存单独标注，驱动未
提供的指标显示 `unknown`。查看远端硬件无需在远端安装 Tersh。

同时正式发布地点记录、日志跟随、结构化预览、最近任务、主机事件与注意项等
工作流程改进，以及安装时的 WSL SSH 生命周期补丁。提供 macOS Apple Silicon、
Linux x86_64、Linux ARM64 三种下载包及对应 SHA-256 校验文件。
